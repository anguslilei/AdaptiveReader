## Commands run

```bash
python -m unittest discover -s dev-docs/prototypes/epub-semantics/tests -v
python dev-docs/prototypes/epub-semantics/__main__.py CONTROLLED.epub
# macOS CI, after xcodegen generate:
xcodebuild build -project vreader.xcodeproj -scheme vreader \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/adaptive-reader-build CODE_SIGNING_ALLOWED=NO
```

The controlled EPUB was generated with `tests/fixtures.book`; the real CLI was
invoked via subprocess, JSON parsed and every block run resolved with resolve_run.
The same process is automated by CLI subprocess and source-round-trip suites.
CLI interruption policy is exercised with an injected KeyboardInterrupt, not an
OS signal/device test. Do not interpret that case as signal timing validation.

Synthetic measurement recipe: construct XHTML body with 5,000 paragraphs,
each `第N段：` + `中文阅读样本` repeated 12 times + `<em>中😀é</em>尾`;
wrap original bytes as SourceResource, time extract_section with perf_counter,
measure Python allocations with tracemalloc, parse original bytes and resolve
all output runs. No real-book throughput claim. Before path caching:
1,288,953 bytes / 10,002 XML nodes / 15,000 runs / 1.122 seconds /
18,092,642 Python traced peak bytes. libxml2 C allocations are excluded.

Wide-chapter recipe: body with 4k/8k/16k `<p>x</p>` siblings, time extraction
without tracemalloc. Before cached paths: 0.176 / 0.360 / 1.014 seconds;
after: 0.049 / 0.101 / 0.203 seconds. One local sample each, no latency SLA.

## Observations

ZipFile streamed reads alone accepted forged shorter central length + prefix CRC
for STORE and DEFLATE. A bounded raw stream and complete stream/length/CRC checks
closed this measured source-fidelity gap. ZIP local header validation remains
stdlib-backed. XML is strict, rejects unsupported encodings/DOCTYPE and never
repairs malformed HTML. Source offsets are logical DOM UTF-16, not byte offsets
or CFIs. Structural whitespace is preserved, including NBSP and inline separators.

Source metadata guards are not an immutable snapshot guarantee; libxml2 parsing
is bounded by input size but post-parse node limits/cancellation cannot preempt
inside its C call. Experimental limits can reject valid real books. No new
app dependency, renderer change, persistent schema or data migration is made.
